# MHW 存档读取与 Steam Cloud 路径（2026-09-27）

状态：原云存档四个文件已通过校验并恢复；DLC 修复包在 AYN 显示 Iceborne 主菜单，
原“缺少 DLC / 继续会丢失设置”警告消失。原角色场景和受控正常退出/重启尚待验。

## 已确认的问题

前一轮 [启动路径修复](mhw-startup-20260927.md) 解决了根目录启动导致的零尺寸资源错误，
但到达首次存档提示并不证明存档接通。进一步核对源码和设备发现三个独立问题：

1. `XrGameSteamClient` 只写入通用显示名，没有设置 `account_steamid` 或
   `[user::saves] local_save_path`。`saves_folder_name` 还放在错误的 section。
   固定版本 GBE 因而生成另一 Steam 身份，并使用 `%APPDATA%/GSE Saves`；
   Steam AutoCloud 则把文件放在 `Steam/userdata/<accountID>/<appID>/remote`。
2. Steam CM 的 Cloud 下载响应返回了三个实际存储主机：
   `steamcloud-hkg.oss-accelerate.aliyuncs.com`、`steamcloud-sgp.oss-accelerate.aliyuncs.com`、
   `steamcloudhk2.blob.core.windows.net`。这些 HTTPS 请求被全局白名单送到关闭的 loopback
   代理端口，日志为连接 `[::1]:9` 失败，未下载原云存档。
3. 上游 `migrateGSESavesToSteamUserdata()` 在启动同步前，会以 `REPLACE_EXISTING`
   把无账户归属证明的 GSE 文件移到当前 Steam 账户目录；当云下载随后失败，游戏又从
   被移空的 GSE 路径读取，重复提示没有存档，并有覆盖现存本地数据的风险。

私有现场中，Cloud 列表仍列出 `SAVEDATA1000`，原时间为 2025-04-15 21:07:27 +08:00，
大小 11,284,704 字节。设备现存同名文件的时间为本轮首次创建时的
2026-09-27 14:20:14 +08:00；已备份，不能把这份新文件称为原云存档。
当前文件 SHA-256 为 `68b50c6b57d56ec2ad8304f78666d2076adb6bf4594c222644ccfb7c56749d72`。
没有证据说明原云端数据已丢失；恢复成功仍需下载完整性检查和游戏内角色验证。

## 修复范围

- 客户端使用已登录或持久化的同一 Steam64 身份，推导无符号 accountID，
  存档根目录指向 `C:\Program Files (x86)\Steam\userdata\<accountID>`。
  GBE 在其后追加 `<appID>/remote`，与 AutoCloud 相同。缺少合法身份时明确报错，
  不再生成随机身份。原游戏目录别名保持不变。
- picoXr 停用同步前的破坏性 GSE 迁移；已有 GSE 文件保留，不能自动归入另一账户。
  已有 Steam 存档无需复制、移动或创建存档目录符号链接。
- 仅从已认证 CM Cloud 响应构造的请求，可为上述三个精确 HTTPS 主机取得单请求路由；
  不放开 Azure/Aliyun 域名后缀，不改变全局白名单，不允许跨主机重定向。
- picoXr 云下载先写同目录临时文件，验证解压后长度与 CM 文件列表 SHA-1，再原子替换。
  失败或不完整下载不截断原存档。

原始日志含账号和签名 URL，只保留在仓库外 `xrgame-native-evidence/mhw/20260927/saves/`；
不把账号值、存档或下载凭据写入公开仓库。

### DLC 与目录复核

`configs.app.ini` 原来只有 `unlock_all=0`，完全没有传入已有 DLC 授权。当前 CM license
缓存含 26 个 MHW DLC 的有效授权，包括 Iceborne `1118010`；Iceborne 不在父游戏旧
`dlc_app_ids` 列表中，但独立 app 行的 `dlc_for_app_id=582010` 正确，因此不能只扫描父列表。
高清材质 DLC `960781` 的 `582012` depot 已安装。不能把 app 元数据或 PICS token
本身作为购买证明。

修复从父子关系查询 DLC，再以有效 package license 的明确 app ID 授权取交集；排除
pending、expired、未激活和取消授权。无独立 depot 的已购内容无需另下文件；有 Windows
depot 的 DLC 需有对应已安装 depot。仍固定 `unlock_all=0`，不增加未授权 DLC。

通用目录漏项是 `GetAppInstallDir`：GBE 未配置 `[app::paths]` 时从客户端 DLL 目录和
当前工作目录择短返回，不能保证是游戏根目录。现在明确配置指向 prefix 内的安装目录别名，
适用于所有内置 x64 Steam client 启动；原始游戏文件不移动。
MHW 的**实际 EXE 启动目录**仍单独使用非根目录别名：A/B 已证明该游戏失败，但没有证据
说明所有盘符根目录启动都失败。Hades II 使用 `A:\Ship`，其他未验证游戏保持既有路径；
不能把这轮测试表述为全部游戏兼容性通过。
