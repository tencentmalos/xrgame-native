## 实现

- 根 `foundation/` 是正式构建子仓，仅编译 `modules/debugbus` 的注册表。
- `DebugBusService → JNI → Foundation DebugCommandRegistry` 提供 bridge/status/runtime/
  processes/modules/present；具体合同和后续 guest 接入点见 [使用文档](../debugging/debugbus.md)。
- 服务仅存在于 `picoXrDebug`，受 DUMP 权限保护；不新增 TCP 监听或端口转发。
- Present 查询不获取 renderer/GPU 锁；有界 trace 仍复用现有日志路径，不改变显示方式。
- APK 来源清单、native build info 包含本次依赖、源码哈希和实载诊断库身份。

## 失败与修正

1. 首包 APK `809f1ed47c976282a9804c9646540cbde43f0623210ae76da2209c7368b4da24`
   默认模块表限制 256 个，AYN 返回 `truncated=true`，诊断库在列表之外，初次身份断言失败。
   增加完整库名筛选后，按库名核对 Build ID 通过；仍保留默认列表上限。
2. 首次最终包 live 测试过早在加载期要求 3 秒内采完 30 帧，断言失败；游戏加载后余量自行
   归零。改成在已显示菜单时按余量做有界等待，没有修改实现来伪造完成。
3. AYN 的 `am stopservice` 实际输出 `Service stopped`，进程返回码却为 255，导致 Python
   客户端误报。改为识别明确的 framework 结果，并通过之后 3 次线程清理验证，未把任意
   非零码都视为成功。

首包、首次失败日志、全部最终请求、截图、native build info 和 APK 审计在仓库外
`xrgame-native-evidence/debugbus/20260927/`，最终测试在其 `final/` 目录。未提交、推送或发布。

见 [独立记录](mhw-startup-20260927.md)；不把后续结果计入本次 DebugBus 验收。
