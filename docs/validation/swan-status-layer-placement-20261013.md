# Swan：状态层位置调整（2026-10-13）

## 问题

用户反馈两点：

- **立体模式（Alyx）**：状态层在 2.5 m 处，场景里更近的物体会挡在它前面，但 quad 层总是画在场景之上，造成穿插和辐辏冲突。用户希望它离人更近、更靠上，抬头能看到即可。
- **2D 大屏**：曲面屏时状态层与屏幕穿插。
  - 原因：状态层按平面屏的左上角放，左端离人比圆柱面更远。
  - 下沿在视线方向上落到了圆弧上沿以下，又画在屏幕之上。

## 改动

代码在 `app/src/main/cpp/xrimmersive/xr_perf_hud.cpp`。

- **立体模式**：
  - 面板中心距头部 1.0 m，在头部偏航方向上水平居中，仰角 35°；平视时在视野上沿外，抬头可见。
  - 大小 0.8×0.08 m，与原来 2.0 m 宽、2.5 m 远时的视角大小相同。
  - 1.0 m 与 Swan 1.5 m 焦平面相差约 0.33 屈光度。
  - 面板仍保持竖直、平行于偏航方向的正前平面，沿用 10-12 用户确认的朝向。
- **2D 大屏**：
  - 下沿与屏幕上沿的间隙从 0.25 个面板高加到 0.6 个。
  - 曲面屏时，面板沿圆弧左对齐，贴在圆柱面上朝向圆心。抬高量按面板两端到轴心的实际距离计算，保证两端也不低于圆弧上沿。
  - `submitPerfHud` / `PerfHud::fill` 新增圆柱半径参数，平面屏传 0。

- 设备：Swan（Pico B3110），boot id `6d4335a5-667c-426d-815b-1a82edaa0fbb`。
- MHR 80 英寸大屏，1.5 m，屏幕约 1.78×1.0 m。读的是 DebugBus `vr_hud status` 的 `anchorLocal`：

| 屏幕 | 面板中心（LOCAL） | 与计算值 |

| 平面 | (-0.29, 0.63, -1.50) | 一致：宽 1.2 m 左对齐，下沿离屏幕上沿 7 cm |
| 曲面 | (-0.28, 0.67, -1.47) | 一致：圆弧角 -0.193 rad，两端扩展系数 1.077 |

- 头显当时平放在桌上，没有人戴，截图看不出遮挡关系，所以位置只按数值核对。
- 立体模式的设备复测没有做：
  - 上一轮 Alyx 会话被装包强制结束，没走退出同步，再次启动大概率又会弹出 app 记录变更号滞后造成的假冲突，已单独提出该问题。
  - 立体模式只改了放置常量，放置函数本身没变。
- 本轮最初两次用曲面屏启动 MHR 时，游戏都在约 35 s 后自行退出，此时 D3D12 设备尚未创建。
  - 改回平面屏后正常；再切回曲面屏，第三次也正常。
  - 曲面屏标志只影响 app 侧合成，判断前两次是装包强制结束 Alyx 后的偶发状态，与本改动无关。原因未查明。

## 2026-10-14 修正：立体模式的仰角按视场角计算

用户在旁观者画面（xr 源）里看 Alyx，指出状态层没有「更靠上」。复查：

- 上文「平视时在视野上沿外」没有在设备上核对过。Swan 运行时报告的眼视场为左右 ±47.5°、上下 ±43.0°（新加的日志 `XR eye FOV`）。仰角 35° 的面板下沿在 32.7°，平视时仍在视野里，位于上部约五分之一处。
- 改为按运行时的向上视场角放置：面板中心仰角 = 向上半视场 + 面板半高（2.3°）+ 4° 余量，限制在 35°–60° 之间；拿不到视场时仍为 35°。距离 1.0 m、大小、竖直朝向都不变。视场在会话第一次定位眼视图时传给 HUD（`PerfHud::setViewTop`），变化时重新放置。
- Swan 上的结果（APK `f829a7445ac7f10826a5d6cb6d2b86313c7de0a7b76258e0c9c0ca464d771cac`，Alyx）：日志 `Performance HUD placed in LOCAL space at (-0.05, 0.74, -0.60), 49.3 deg up (view top 43.0 deg)`。同一局的 `xr` 截图视线俯仰 -1.4°（几乎平视），画面里没有状态层；面板下沿比平视的视野上沿高约 4°，抬头约 6° 以上即可看到。
- 头显平放在桌上，没有人戴，所以「抬头可见」按数值核对，没有人工确认。
