# Swan：Steam 云存档反复冲突与上传失败（2026-10-10）

设备 Swan（Pico B3110，Android 16）。游戏 Half-Life: Alyx（546560）。测试账号的存档经 Steam 中国云存储（`steamcloud-hkg.oss-accelerate.aliyuncs.com`）同步。

## 现象

- 启动时反复弹「存档冲突」（本地对远程）。用户选择一侧后，下次启动又冲突。
- 15:23 起，每次启动都提示「同步存档失败：UpdateFail」，启动被中止。重试后又变成冲突，选「保留本地」照样失败。

来回删除、下载的这 3 个文件是 Alyx 的关卡过渡存档 `a1_intro_world.hl1/hl2/hl3`，游戏运行时会自己创建和删除它们。

## 原因

1. **删除从未执行。** 本地删掉的文件只在 `BeginAppUploadBatch` 里声明为「待删除」，没有调用 `ClientDeleteFile`，所以云端一直保留（变更号 6 时这 3 个文件仍是 `Persisted`）。下一次对账时，这些文件既不在磁盘上、也不在缓存里，被当成「从未同步」下载回来；游戏再删掉它们，循环往复。每发一个批次，云端变更号都会 +1。
2. **变更号与冲突。** 批次成功才会把新变更号记到本地。一旦某次没记下（10:16；或退出同步时应用被关闭），下次启动就会同时发现「本地有改动、云端也变了」，于是报冲突。
3. **「提交失败」其实是云端已有相同内容。** 对 `a1_intro_world.*`，`ClientBeginFileUpload` 没有返回任何上传块（日志里这些文件没有一条 `Uploading to`），随后的提交报告 `file_committed=false`。
   - Steam 对 SHA 与云端副本相同的文件不要求上传任何块，这时的提交也不算新的提交。
   - 时间线吻合：
     - 14:37 的退出同步已把这 3 个文件传上云端，但应用在 14:43 被关闭，新的变更号没记下；
     - 15:23 再次上传同样的内容，于是 0 块、提交 false；
     - 当时云端还没有 `temp.jpg`，所以它正常上传，提交成功；
     - 之后的重试中，4 个文件都已在云端，全部是 0 块 + 提交 false。
   - 佐证：15:42 选「保留远程」下载后，设备上的存档与 15:39 的本地备份逐字节一致（8 个文件 SHA-256 全部相同）。
   - JavaSteam 的 `SteamCloud.beginFileUpload` 会丢掉 EResult，所以当时看不到「开始上传」本身是成功的。出站白名单没有拦截（`steamcloud-hkg` 已放行）。
4. **XRGame 的判定。** picoXr 把「提交失败」当作整个批次失败（`2ac13287b`、`6193851f6`），所以批次以 `EResult.Fail` 结束，不记变更号，并返回 UpdateFail。上游只记日志、照常按成功处理：失败的文件不会再传，这实际是丢存档。我们的判定是对的。问题在于失败之后没有出路：云端变更号照涨，冲突无法消除，启动也被拦住。

## 修改（XRGame，`XrGameCloudRpc`）

- **直接调用 Cloud 服务**：「开始上传」「提交」「删除」都直接调用 Cloud 统一服务，并记录 EResult。「开始上传」还记录 `encrypt` 和每个块的 HTTP 方法、长度、显式请求体大小；URL 和请求头不进日志。
- **开始上传被拒**（或要求加密）：这个文件不上传、不提交，批次判为失败。
- **云端已有相同内容**：「开始上传」成功但返回 0 个块，视为云端已有这份内容。提交报告未提交也算成功，并记录 `Steam Cloud already holds …`。
- **不申请加密**：请求时 `canEncrypt=false`，因为这条路径只会发送明文文件。
- **按服务端要求发送分块**：使用块里指定的 HTTP 方法；有显式请求体时发送它（例如多段上传的完成请求），否则发送文件内容。块上传失败时记录 HTTP 状态码。
- **真正执行删除**：批次里声明的删除逐个调用 `ClientDeleteFile`。
  - 护栏：本地扫描为空、要删的超过 8 个，或超过上次已同步文件的一半时，判为路径异常，不删云端文件，只记日志。
- **上传失败时可以继续启动**：「同步错误」对话框（仅 UpdateFail）增加「保留本地存档并启动」，以跳过云同步的方式继续启动。下载失败和未知失败保持原样，因为这两种情况下本地存档可能不完整。
- **单元测试回退**：拿不到 Cloud 服务时（只有单元测试会这样，测试里 mock 的是 `SteamCloud`），走原有的 `SteamCloud` 路径。

单元测试：`SteamAutoCloudTest` 50/50，`XrGameCloudRpcTest` 4/4，`XrGameRuntimeTest` 5/5。
